# 5. Прототипирование

## 5.1. Черновые схемы

Файлы `Wireframe_S1`–`Wireframe_S11` показывают зоны desktop без декоративного оформления. Переход от общей архитектуры к зонам позволяет проверить, хватает ли пространства холсту и не смешаны ли инструменты документа с настройками профиля.

| Экран | Зоны и назначение |
|---|---|
| S1 | Описание продукта слева; форма и два пути входа справа |
| S2 | Шапка действий, навигация, поиск, сетка проектов |
| S3 | Шапка, инструменты, параметры, холст, правая панель, статус |
| S4 | Общий редактор; список слоёв, видимость, непрозрачность, имя |
| S5 | Общий редактор; список понятных эффектов |
| S6 | Контекст редактора и диалог параметров экспорта |
| S7 | Общий редактор; последовательность последних состояний |
| S8 | Общий редактор; пресеты размеров и палитра |
| S9 | Навигация; карточка профиля, тема, данные |
| S10 | Навигация; поиск и карточки форматов |
| S11 | Навигация; таблица участников и статусов |

Ширина desktop 1440 px, высота 960 px. В рабочей области верхняя панель 72 px, инструменты 64 px, правая панель 296 px. Основной контент начинается после панели параметров. Эти размеры описывают макет, а не ограничения будущего окна приложения.

## 5.2. Финальные схемы

`Prototype_S1`–`Prototype_S11` сохраняют элементы, подписи и геометрию в монохроме. Цветные макеты развивают ту же структуру. В финальном прототипе нельзя терять подписи и состояния ради декоративной картинки.

## 5.3. Интерактивный прототип Figma

Файл: https://www.figma.com/design/FPaA4Y8YO1qcxkyT9T2xvW

Старт: https://www.figma.com/proto/FPaA4Y8YO1qcxkyT9T2xvW

Прототип предназначен для проверки навигации и последовательности состояний. Поля и рисунок заранее заполнены. Нажатие на инструмент показывает следующий экран сценария; произвольный ввод, рисование и настоящее скачивание не реализуются. Это нормальная граница данного учебного прототипа, которую нужно озвучивать участнику теста.

Сценарии: вход и создание; работа со слоями; применение эффекта и отмена; экспорт; профиль и тема; регистрация и пустой список. Ошибка размера имеет отдельный кадр и путь исправления. Кнопки закрытия возвращают к исходному экрану.

## 5.4. План пользовательской проверки

Попросить начинающего пользователя без подсказок создать проект, изменить активный слой, применить фильтр, отменить и найти экспорт. Записывать успех, ошибочный выбор и моменты замешательства. Не объяснять интерфейс до попытки. После теста спросить, где, по мнению участника, хранятся данные и что означает активный слой. Интервью пока не проведены; техническая проверка связей не заменяет такой тест.

## 5.5. Фактическая техническая проверка

В Figma созданы 78 фреймов на трёх страницах и 424 зоны нажатия. Проверка по API не выявила потерянных целей или зон за пределами фрейма. На странице прототипа найдено 1336 редактируемых текстовых узлов. В Present вручную пройден путь вход → проекты → создание → холст → экспорт → завершение. Все остальные ветви вручную не пройдены. Результаты: design/export/figma-verification.json. Это проверка связей, а не пользовательское исследование.
